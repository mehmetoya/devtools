About number bases

  • Decimal (base 10) uses digits 0–9. Binary (base 2) uses 0 and 1; each digit is one bit. Octal (base 8) uses 0–7; one digit is three bits, as in Unix permissions like 755. Hexadecimal (base 16) uses 0–9 and A–F; one digit is four bits (a nibble), two digits are a byte.
  • Prefixes 0x, 0b and 0o are accepted, as are spaces and underscores used as digit separators (1111_0000).
  • Negative numbers are shown with a minus sign in every base. The two's complement table shows how a fixed-width signed integer stores the value; a pattern such as FF reads as 255 unsigned or −1 as a signed byte.
  • All arithmetic uses JavaScript BigInt, so there is no precision loss for large values.

Privacy

Everything is computed in your browser. Nothing is sent, stored or logged.

Questions

How do I convert decimal to hexadecimal or binary?

Type a number in any of the four fields (decimal, hexadecimal, binary or octal) and the other three update instantly. For example, 255 is FF in hex, 11111111 in binary and 377 in octal. Prefixes 0x, 0b and 0o are accepted, and spaces or underscores can separate digits.

How are negative numbers shown in binary or hex?

Each base field shows a minus sign, such as -FF. The two's complement table shows how 8-, 16-, 32- and 64-bit signed integers store the value. For example, -1 is stored as FF in 8 bits, and that pattern reads as 255 unsigned.

Can it convert very large numbers without losing precision?

Yes. All arithmetic uses JavaScript BigInt, so integers of any size are exact, up to 50,000 digits of input. The converter handles integers only, not fractions. It also shows the bit length, the bytes needed and the value with thousands separators.

Why is one hex digit equal to four bits?

Base 16 has 16 = 2^4 digit values, so each hex digit maps to exactly four bits (a nibble) and two hex digits make a byte. Octal digits map to three bits, which is why Unix permissions such as 755 are written in octal. Turn on "Group binary in nibbles" to see this grouping.
