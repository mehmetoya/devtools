JSON to TypeScript

Generate TypeScript interfaces or type aliases from a JSON sample.

JSON input
TypeScript

About this tool

Paste a JSON sample and get TypeScript declarations for it. Every nested object becomes its own interface (or type alias) named after its key, and arrays become T[].

Type mapping

  • Numbers → number, text → string, true/false → boolean, null → null.
  • Empty arrays → unknown[]; arrays with mixed values → unions such as (string | number)[].
  • Objects inside arrays are merged: a key missing from some items is marked optional (?), a key that is sometimes null gets | null.
  • Keys that are not valid identifiers (e.g. first-name, or the empty key "") are quoted.

Options

All properties optional adds ? everywhere, useful for partial payloads. camelCase renames keys — only use it when your code maps names, since the types will no longer match the raw JSON.

Privacy

Code is generated entirely in your browser. The JSON you paste is never uploaded, stored or logged.

Questions

How do I convert JSON to a TypeScript interface?

Paste a JSON object or an array of objects and the TypeScript declarations appear instantly. Every nested object becomes its own interface named after its key, and arrays become T[]. You can switch to type aliases, rename the root type, drop the export keyword, then copy the result or download it as a .ts file.

How are optional and nullable properties detected?

Objects inside an array are merged into one type. A key missing from some items is marked optional with ?, and a key that is sometimes null gets | null. For example, [{"id":1},{"id":2,"tag":null}] produces id: number; and tag?: null;. The "All properties optional" option adds ? to every property, which suits partial payloads.

Should I use an interface or a type alias?

For plain object shapes both work the same, so pick whichever your codebase uses. Interfaces can be extended and merged by redeclaring them; type aliases can also name unions and arrays. When the JSON root is an array, the tool always emits a type alias such as type Root = RootItem[]; plus an interface or alias for the item.

What happens to keys like first-name or mixed-type arrays?

Keys that are not valid identifiers, such as first-name, are quoted: "first-name": string;. Arrays with mixed values become unions, for example (string | number)[], and empty arrays become unknown[]. All JSON numbers map to number, so integers larger than 2^53 lose precision unless you parse them with a bigint-aware parser.
